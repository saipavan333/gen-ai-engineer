1) Connect and discover (no integration code written for this server)
======================================================================
  server='store-support'  negotiated protocol version=2026-07-28
  tool lookup_order: Get status, item and total (in rupees) for an order id like ORD-12345.
       input schema: {"type": "object", "properties": {"order_id": {"title": "Order Id", "type": "string"}}, "required": ["order_id"], "title": "lookup_orderArguments"}
  tool search_policies: Keyword search over the store's policy pages. Returns the best k pages with their ids.
       input schema: {"type": "object", "properties": {"query": {"title": "Query", "type": "string"}, "k": {"default": 2, "title": "K", "type": "integer"}}, "required": ["query"], "title": "search_policiesArguments"}
  resource policies://index -> 14 lines, e.g. ['ship-01: Standard shipping', 'ship-02: Express shipping', 'ship-03: Address changes']

3) Trust boundary
======================================================================
  Look: the model only ever saw tool NAMES, DESCRIPTIONS and RESULTS that the server chose to send.
  A malicious server can put instructions in any of those (tool poisoning / indirect injection),
  so treat third-party servers like third-party code: pin versions, least privilege, and keep
  approval gates for actions in YOUR client code (lab 04, lab 07).
